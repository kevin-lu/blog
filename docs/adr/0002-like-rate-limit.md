# ADR 0002: 点赞功能限流策略

## 状态

已接受

## 背景

点赞功能需要防止恶意刷赞攻击，确保系统安全和数据可靠性。

## 决策

### 限流策略

**决策**：使用 IP 限流，同一 IP 每分钟最多 10 次点赞操作。

**实现方式**：
- 使用 `flask-limiter==3.5.0`（现有依赖）
- 限流粒度：IP 地址
- 限流窗口：1 分钟
- 限流值：10 次操作

### 限流范围

**决策**：仅对点赞 API 端点限流，不影响文章浏览等读操作。

限流端点：
- `POST /api/v1/articles/<id>/like`
- `DELETE /api/v1/articles/<id>/unlike`

## 权衡

### 正面影响

- ✅ 有效防止刷赞攻击
- ✅ 保护数据库写入性能
- ✅ 实现简单，复用现有依赖

### 负面影响

- ❌ 同一 IP 的多个用户共享限流额度（但 10 次/分钟足够正常使用）
- ❌ 动态 IP 用户可能误判（概率低，可接受）

### 替代方案

#### 方案 A：用户级限流
按用户 ID 限流（登录用户）。

**为什么不选**：
- 未登录用户无法限流
- 实现复杂度更高

#### 方案 B：设备指纹
使用浏览器指纹识别设备。

**为什么不选**：
- 实现复杂度高
- 隐私合规风险
- 当前场景过度设计

## 合规性

与现有安全策略一致：
- 复用 `flask-limiter`（已有依赖）
- 符合项目限流模式（参考现有 API 限流）

## 备注

如果未来需要更精细的限流，可考虑：
1. 结合用户 ID + IP 双重限流
2. 使用 Redis 实现分布式限流
3. 添加异常行为检测（如短时间内大量点赞）
